# Task 9 brief: UI, observability, operations, and golden evaluation

## Objective

Make the supported workflows complete and explainable through the UI and operational surfaces, and add executable evaluation/recovery gates without claiming unavailable live infrastructure.

## Required behavior

- UI supports ownership and human-browser-auth handoffs; durable refresh/resume/cancel/retry/failure states; evidence, schemas, auth, effects, risk, request plan, verification checks, provenance, and version-conflict review; verify/publish/copy-script/download/self-host/installed-check actions.
- Website, OpenAPI, and GitHub flows remain independently truthful. Unsupported/high-risk inputs show precise diagnostics and never appear production-ready. No direct API/database/environment manipulation is required for a supported journey.
- One workflow ID reconstructs durable events for every task, provider/tool/model call, state change, evidence/artifact, verification, retry, recovery, cancellation, and terminal stop. OTel/Langfuse/PostHog exports are redacted, correlated, batched, and non-authoritative.
- Langfuse uses real nested observations with hashes/versions/cost/latency/outcome; PostHog emits only the documented funnel with pseudonymous UUID/org grouping and no autocapture/profiles/replay. Metrics/alerts cover queue age/depth, leases, retries, provider/browser/model errors, verification failures, publish→install conversion, DB pools, reconciliation/retention, and telemetry drops.
- Add executable golden/evaluation fixtures for authenticated website read, confirmed reversible mutation, unsupported/high-risk, prompt injection/poisoned output, OAS 3.0/3.1/3.2 and auth modes, GitHub draft PR, ownership/auth failures, crash/resume/cancel, exact hosted/self-host installs, and native/compatibility WebMCP. Deterministic checks are release gates; model judges remain diagnostic.
- Add reproducible deployment/recovery checks and runbooks for provider outage, stuck workflow, leaked browser session, bad model/parser/compiler, compromised artifact, GitHub revocation, rollback, and restore. Pin versions and fail promotion on drift. Do not fabricate live deployment success when infrastructure is absent.

## Scope guidance

Inspect existing project UI, event/telemetry modules, worker shutdown/reconciliation/retention paths, CI quality workflows, and e2e/golden tests. Keep the database event stream authoritative and preserve all Task 1–8 security, RLS, idempotency, cancellation, artifact, and installation invariants. Prefer additive adapters/contracts and hermetic tests over new infrastructure.

## TDD and gates

Start with RED tests for each missing user-visible state/action, event/trace redaction and correlation, funnel identity, golden safety-negative cases, and recovery/runbook checks. Then run affected/full trusted suites, typecheck/lint/source/security/diff, and explicit environment-gated PG/browser/provider checks. Record every skipped live gate honestly.

## Non-goals

No new workflow engine, Redis/cache/model swarm, live credential fabrication, autonomous GitHub merge, or weakening of fail-closed diagnostics.
