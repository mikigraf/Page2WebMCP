# Task 8 brief: exact candidate verification, publication, and installation

## Objective

Complete the common website/OpenAPI release boundary: compile the exact reviewed plans once, verify those exact bytes against a real target-page contract, publish identical immutable hosted/downloadable artifacts, and verify a normal installed page automatically registers the expected WebMCP tools. This task must resolve the Task 1 trusted-loader dependency rather than accepting compiler replay alone as proof of installed bytes.

## Required behavior

- Candidate verification executes the exact candidate bytes and manifest against an isolated target-page adapter with schema, origin/authentication, read, reversible mutation, confirmation, final-state, replay/idempotency, tool-selection, cancellation, and secret-leakage checks.
- Verification records typed checks and fails closed for logged-out, forbidden, stale-page, timeout, invalid-output, wrong-state, duplicate-registration, wrong-origin, unavailable-WebMCP, and missing trusted-loader cases. No control-plane or model request is allowed during generated-tool execution.
- Publication is owner-only, review-version/evidence bound, idempotent, immutable, content-addressed by SHA-256, and exposes SHA-384 SRI. Hosted and downloaded bytes must be byte-for-byte identical.
- Add an artifact/CDN boundary with JavaScript content type, immutable cache headers, exact target-origin CORS, `Cross-Origin-Resource-Policy: cross-origin`, hash-matching ETag, no cookies, and no credential-dependent delivery. Test malformed/corrupt/mismatched artifacts and publication races.
- Provide the exact module `<script>` tag, manifest, SRI, target origin, WebMCP/browser compatibility, CSP result, self-host guidance, and previous immutable release. If CSP blocks hosted delivery, offer self-hosting and do not mark installed until the self-hosted hash is observed.
- Installed-target verification loads the normal target page without route interception, injected registration, or synthetic WebMCP harness. It proves the exact release hash was served and executed, that duplicate loads are harmless, and that native/current WebMCP exposes the expected tools. A compatibility shim may be used only as an explicit hermetic test double.
- Remove or bypass any independent Acme release/manual-registration path; Acme and generic website/OpenAPI flows consume the same normal release/install boundary.
- Use explicit hermetic target/CDN/WebMCP fakes where live credentials are unavailable, and make missing live verification controls fail closed. Do not claim live target/browser success.

## Scope guidance

Inspect and extend `apps/control-plane/src/releases.ts`, release/API routes, artifact delivery, verification persistence, Acme registration/tests, compiler runtime, and relevant database contracts. Preserve immutable review/evidence bindings, RLS, idempotency, cancellation, and Task 1–7 invariants. Do not implement OpenAPI/GitHub-specific alternate release formats or add customer initialization code.

## TDD and gates

Write focused RED tests before implementation for exact-byte candidate execution, trusted-loader enforcement, artifact headers/byte identity, CSP self-host fallback, unintercepted installation, duplicate load, and native WebMCP discovery. Then run focused/affected/full trusted suites, typecheck, lint/source/security/diff checks, and ephemeral PostgreSQL/RLS/topology tests. Record skipped live-provider/target gates explicitly in the task report.

## Non-goals

No payments, permission/security changes, passwords, deletion, merge/install side effects, runtime model calls, runtime Page2WebMCP API calls, or live credential fabrication.
